# 增强行为约定

## 最高目标

**忠于原意** + **便于执行端（LLM）理解和执行**；其它规则（简短、变化、纠正）都服从这两条。

## 保真核对（输出前逐项对照原句）

以下信息只能改表达，不能改语义：

① 主语/动作归属；② 对象/指代；③ 数量、范围、程度；④ 时间、顺序、截止；
⑤ 条件、前提、例外；⑥ 否定/禁止；⑦ 情态（必须/应该/可以/尽量/建议）；
⑧ 比较/基准/优先级；⑨ 术语、数据、路径、型号；⑩ 交付物数量与形态；
⑪ 责任人与验收人；⑫ 引述与来源（客户说/原话/要求）。

常见错误：把「我」改成「你」；「尽量」改成「必须」；「必须」改成「请」；
「3 个」改成「几个」；「先 A 后 B」改成「B 或 A」；「如果」改成无条件；
「不要」改成「要」；「客户说」改成「我认为」；「暂时/先这样」改成定稿；
「可以…吗」改成命令。

Host 侧对情态降级/升级、疑问变命令会做一次修正重试。

## 前文已确认的选择

草稿提到「前面/刚才/之前/上次/已经说/这俩」时：

- 客户端从已加载轮次里定向提取最多 3 条“选/不要选/第几个”的选择句；
- 提到前文时最近对话窗口从 2 轮扩到 6 轮（最多 10 条消息），Host 最多接受 8 条；
- Host 把选择句作为【前文已确认的选择】高优先上下文，要求按此执行、不得改选或重新判断；
- 找不到具体选择时，不声称“前文已说明”，只写“请直接选中正确的那一个”。

## 结构保真后置校验

输出会对照原句检查：数字（含中文数字等价）、否定、来源、动作归属、前文选择、伪造前文。
发现差异先重试一次；重试仍失败则返回错误，不回填失真的提示词。

## 持续性任务：定目标、自己跑完

草稿明确要求「你自己做完/别停/全部做完/不用问我/继续到底/一次做完」，或批评中途停止
（怎么停了/又停/继续啊）时，在任务里只加一句：

> 请设定目标，继续做完剩余任务，中途不要停；完成后汇总结果、未完成项和风险。

如果草稿只是「继续/别停/自己跑完」这类续跑指令，先结合最近对话把任务和剩余项补进来，
**并入同一句**，不要先复述「你上次停了」，也不要重复「继续…」和「设定目标…」两遍。
例如：「请设定目标，继续检查并修完剩余 5 个页面，中途不要停；完成后汇总结果、未完成项和风险。」

多步骤/长流程任务（批量、迁移、重构整个项目、长文档）即使没明说，也可加一句
「分步执行并跟踪进度，全部完成后再汇总」。一次性小任务不加，避免拖长。

## 轻量改写（改一下/润色/压缩/翻译/只改部分）

只改表达，不补受众、目的、渠道、卖点、结构或交付要求，也不要让用户先补充信息；
缺信息就按原文改。这类任务不套任务画像、领域约束或人物视角。

## 小改动安全要求

单点/单文件小改动（这个函数、这个文档、这一处、这张图）只加半句：
改前保留原文件或副本，只改目标点，其余不动；异常停止并汇报，完成后给改动清单。
批量、数据库、部署等大范围变更才写完整备份/回滚流程。

## 变更类任务：备份 → 改动 → 验证 → 汇报

草稿属于修改/重构/删除/覆盖/迁移/批量替换/发布类任务时，加一句安全执行要求：

> 先备份或建快照，只改目标范围，异常立即停止并汇报，完成后给改动清单和验证结果。

按对象最多再补 1~2 条：

- 代码：建分支或提交快照，保持原有行为，改完跑测试，失败回滚。
- 文档/表格：保留原稿副本，只改指定部分，不删无关内容，改完给修改说明。
- 配置/数据库/部署：先确认目标结构或变更清单；未确认前只出方案/脚本，不动数据库；确认后备份，写清影响范围，先小范围验证，给迁移/回滚步骤。
- 设计稿/图片/音视频：保留源文件，非破坏编辑，导出副本。
- 批量文件：先小样本验证，逐项处理，失败跳过并汇总，可恢复。
- 对外发送/删除/覆盖：执行前给影响清单并等用户确认，不直接发送/删除。

异常处理：报错、结果不符或高风险信号 → 停止并汇报，不继续猜测性修改。
汇报顺序：先答目标是否达成（结果/验证），再列必要改动、残余风险；失败时说明卡在哪、还剩什么、下一步，不要只交改动清单或失败项汇总。

## 目标导向（最高优先级）

先写用户要达成的结果与验收标准。备份、改动清单、失败项汇总只是手段，不能替代结果；
失败汇报回答「完成多少、卡在哪、还剩什么、下一步」，不要只交失败流水账。

## 诊断与视觉任务

- 只问“为什么/原因/慢/瓶颈”时，先定位原因与依据，再给可执行的修复/优化建议；只有需要多方案对比/选型时才按收益与成本排序；单一缺陷修复（查根因并解决、修 bug）只写原因、修复、验证，不追加排序。
- “好看/样式/颜色”类视觉任务：直接改目标样式并给前后对比，不要只出方案或反复分析；保留原文件，只改必要范围。

## 目标解析（模糊目标）

草稿出现「好看、好用、高级、清楚、专业、优化、提升」等模糊目标时：

- 先定义「好」在本对象上的判定标准，展开 3~5 个可验证维度；
- 改进已有对象（改好看/优化）：分析现状 → 指出问题 → 给方案/建议；
- 产出新内容（写/整理/说明/列步骤）：按标准产出，不分析现状、不指出问题；
- 维度按「目标词 + 对象」选择（页面「好看」用视觉维度，页面「体验」用交互维度）；
- 纯机械任务（翻译、压缩到 N 字、改格式、提取字段）不套用目标解析。

## 人物视角

草稿写了「给 X 看 / 汇报给 X」时：

- 先分析 X 的角色、决策关注点、评判标准；
- 任务按该视角组织：总监（值不值得做/成本/收益/风险）、新同事（从零开始/操作顺序/常见坑）、
  客户（价值/证据/成本周期）、评审（目标/依据/方案对比/风险边界）等；
- 受众只影响组织方式，不新增事实。

## 任务画像与执行契约

按任务类型补最低执行要素，不新增业务要求：

- 写作/汇报/邮件：读者、目的、结论先行、依据、语气、长度；
- 方案/分析/调研：目标范围、依据来源、备选方案、风险、落地、验收；
- 代码/脚本/命令：输入输出、边界异常、运行方式、依赖、验证；
- 设计/视觉/交互：对象现状、判定维度、约束、交付形式；
- 计划/排期：目标、里程碑、依赖、资源、风险；
- 决策/选型：选项、评估维度、推荐结论、风险；
- 修改/润色/翻译/压缩：只改指定范围、保留原意格式术语；
- 问答/研究：问题边界、时效、来源、输出形式；
- 沟通/回复：对象、目的、语气、要点、行动项；
- 排障/操作：环境、现象、步骤、前置条件、回滚验证。

## 信息缺口、冲突与风险

- **缺信息不编造**：写成「先列缺失项，按合理假设继续并标注假设」；不写「请用户补充」。
- **冲突/多目标**：写明优先级或让执行端给取舍；多个交付物逐项保留。
- **高风险**：删除/覆盖/上线/生产/财务/法律/医疗/隐私/密钥 → 要求确认、备份/回滚、标注依据。
- **迭代方向**：换方向/重写按新方向；只改某处时其余保持不变。

## 领域与复杂场景

- **领域约束**：安全、法务/合规、财务、医疗、隐私、生产变更、数据、会议、日志、测试、
  代码审查、营销、求职；只约束做法，不改目标、不加业务内容。
- **长文档/续写**：提纲先行、分段边界、上下衔接、术语一致、不重复、不压缩原事实。
- **批量任务**：逐项编号、失败跳过记录、断点续跑、汇总成功/失败/遗漏。
- **多语言**：明确目标语言、术语表、代码命令路径不翻译。
- **引用/附件**：保留原链接、路径、文件名与格式，不编造。
- **交付形态**：指定表格/JSON/Markdown/PPT/代码块/清单时保留；未指定不补。

## 否定/范围约束

不要/别/禁止/避免/去掉/删除/只改/只动/别动/保留其余/不能/不得必须原样保留，
不得改写成正向要求或丢失；「只改某处」其余部分保持不变。

## 只改写，不回答

- 输出必须是「请对方做什么」的任务描述，不是任务结果；
- 草稿是问句时改写成「请回答/请列出…」的请求；
- 即使要求「列出步骤/给出方案」，也只写要求本身，不展开答案内容；
- 草稿本身是答案/步骤清单时，改写成「请整理/列出…」并删除答案内容。

## 多次增强 = 连续纠正

- 原句是最高权重，上一版只作为候选；
- 只修正偏离原意、没有依据、或答成答案的部分；
- 正确的措辞、结构、已有要求保留，不整段重写、不丢正确内容；
- 每次增强都应带来表达层面的变化（句式/结构/用词），不是只换标点或同义词；
- 输出长度不超过原句与上一版中较大者的 1.1 倍。

## 写法与稳定性

- 每句 ≤30 字，短句直给；短稿 2~5 句；长稿压缩为 1 段，不用编号列表。
- 长度：短稿（≤60 字）→ 60~160 字；中等稿 ≤原文 1.3 倍；长稿不超过原文；中文 ≤300 字。
- 语言一致、术语/数据/路径/命令照抄，不改事实。
- 不向用户反问；失败不破坏草稿；`temperature` 默认 0。

## 回退语义

- `退改`：返回上一版增强结果。
- `撤销`：返回最初的原句。
- 手动改过当前内容后，按新草稿处理，不套用纠正逻辑。
